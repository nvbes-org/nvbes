# Review PR Workflow

## Trigger

Use when asked to review code, a diff, a branch, or a pull request.

## Steps

1. Identify changed files.
2. Read relevant context, not only the diff.
3. Look for correctness, security, performance, data integrity, and test gaps.
4. Report findings first, ordered by severity.
5. Include file and line references.
6. State if no issues were found.

## Output Contract

- Findings.
- Open questions or assumptions.
- Test gaps and residual risk.
- Brief change summary only after findings.
